# 날짜별 변경 의도 기록

큰 작업마다 "왜 하는지(intent) → 무엇을 만족해야 하는지(spec) → 어떻게 하고 무엇을 확인했는지(plan)"를 남긴다.

| 폴더 | 날짜 | 내용 | 상태 |
| --- | --- | --- | --- |
| [20261109-signup-flow](20261109-signup-flow/intent.md) | 2026-11-09 | 회원가입 화면(5단계)·회원가입 API·간편가입 | 로컬 구현·검증 / PR 미승인 |

## 작성 규칙

- 한국 시간 작업 시작일로 폴더를 만든다: 범위가 크면 `YYYYMMDD/`, 작으면 `YYYYMMDD-짧은-주제/`.
- 폴더마다 `intent.md`(의도), `spec.md`(수용 기준), `plan.md`(실행·검증 기록)를 둔다.
- 실제 Git·코드·검사 결과만 완료로 적는다. 사람의 승인·배포·운영은 증거 없이 적지 않는다.
- 담당자는 실제로 정해지기 전까지 "미배정"으로 둔다.
- 기획(PRD)과 다른 결정은 [`docs/tasks.md`](../docs/tasks.md) "열린 질문"에도 적는다.
