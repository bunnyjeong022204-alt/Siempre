# Exception Scenarios

Siempre 페르소나별 AI 선택과 예외 흐름 초안 · 2026-11-09

기준: [상세 페르소나](Siempre_상세_페르소나.md), [MVP PRD](../PRD/Siempre_MVP_PRD.md).
이 문서는 기획 시나리오다. PRD에 없는 예외 처리 방식은 제안이며 구현 완료를 뜻하지 않는다. AI는 페르소나 자체보다 지금 요청한 작업에 따라 선택한다.

## 공통 흐름

요청 입력 → 작업 유형 판단 → 담아 둔 AI 확인 → 예상 AI·차감량 표시 → 실행 → 결과 확인 → 다음 작업으로 연결

각 단계는 사용자가 순서대로 요청한다. “대본부터 영상 완성까지 한 번에 자동 실행”하는 기능은 MVP에 포함하지 않는다.

| 요청 유형 | 기본 자동 선택 | 기본 AI를 담지 않았을 때 |
|---|---|---|
| 대본·카피·보고서 등 글쓰기 | Claude Sonnet | Qwen Plus |
| 번역·요약·일반 분석 | Qwen Plus | Mistral Large |
| 간단한 분석 | Mistral Large | Qwen Plus |
| 깊은 비교·추론·코딩 | Claude Opus | Qwen Max |
| 인사·감사 등 가벼운 대화 | Mistral Small | Qwen Plus |
| 음성 생성 | ElevenLabs | 대체 AI 없이 담기 안내 |
| 이미지 생성 | Nano Banana | 대체 AI 없이 담기 안내 |

대체 AI도 담지 않았다면 실행을 멈추고 필요한 AI를 안내한다. 페르소나는 시작 예시와 추천 구성을 정하는 데 사용하며, 실제 라우팅은 요청 내용과 대화 맥락을 따른다.

## 1. 김도윤 · 1인 유튜버

**상황:** 금요일까지 생활 경제 영상의 대본·내레이션·썸네일을 준비해야 한다.

**기본 흐름**

1. “월급 300만 원으로 저축하는 방법, 8분 대본 써줘.”
   → **Claude Sonnet**: 대본 작성.
2. “도입부를 더 짧게 하고 이 숫자는 수정해줘.”
   → **Claude Sonnet**: 앞 대본 수정.
3. “확정한 대본을 차분한 목소리로 읽어줘.”
   → **ElevenLabs**: 확정 대본의 음성 생성.
4. “이 영상의 썸네일 후보 3개 만들어줘.”
   → **Nano Banana**: 확정 대본의 주제·숫자를 반영.
5. 결과를 내려받고 AI별 사용량을 확인한다.

| 예외 발생 | 처리 흐름 제안 |
|---|---|
| 음성을 만든 뒤 대본의 금액을 변경함 | 기존 음성은 이전 대본 기준임을 알림 → 음성도 다시 만들지 선택 → 예상 차감 표시 → 재생성 |
| 음성 글자 수나 이미지 장수만큼 크레딧이 부족함 | 필요한 양 안내 → 짧은 구간만 음성화·이미지 장수 축소·추가 충전 중 선택 → 선택한 범위로 재개 |
| ElevenLabs를 담지 않음 | “음성 생성에는 ElevenLabs가 필요해요” → 구독에 담기 또는 대본만 내려받기 |

**핵심:** 대본을 고쳤다고 이미 생성한 음성·이미지까지 자동으로 바뀌지는 않는다. 어느 버전을 사용했는지 보여 주는 것이 필요하다.

## 2. 박서연 · 마케터

**상황:** 신학기 캠페인의 SNS 카피·이미지·영문 문구를 준비한다.

**기본 흐름**

1. 브랜드 말투, 대상 고객, 행사 조건 입력.
2. “인스타그램 광고 문구 3개 써줘.”
   → **Claude Sonnet**.
3. “두 번째 문구로 캠페인 이미지 만들어줘.”
   → **Nano Banana**.
4. “이 문구를 해외 고객용 영어로 번역해줘.”
   → **Qwen Plus**.
5. 결과를 내려받아 기존 사내 승인 절차에 전달한다.

| 예외 발생 | 처리 흐름 제안 |
|---|---|
| 대상을 대학생에서 학부모로 변경함 | 변경 조건 확인 → Claude로 카피 수정 → 기존 이미지·번역도 수정할지 선택 |
| 이미지에 행사 날짜·가격이 틀리게 표현됨 | 문구를 확인하도록 안내 → 이미지 재생성 또는 배경 이미지만 받고 글자는 외부 편집 도구에서 입력 |
| “카피를 써줘”와 “캠페인 전략을 비교 분석해줘”가 섞임 | 먼저 카피 작성인지 전략 분석인지 확인 → 작성은 Sonnet, 깊은 분석은 Opus → 비용이 달라지면 실행 전 표시 |

**핵심:** 단순 문구 수정에 매번 고난도 모델을 쓰지 않는다. 브랜드 조건과 확정된 행사 정보를 다음 AI에도 전달한다.

## 3. 정민준 · 대학생

**상황:** 영어 자료를 이해하고 발표 개요를 준비한다.

**기본 흐름**

1. Qwen·Mistral 등 AI 2개 이상을 무료 단계로 담는다.
2. “이 영어 발췌문을 번역하고 핵심 주장 3개로 요약해줘.”
   → **Qwen Plus**.
3. “이 부분을 쉬운 예시로 설명해줘.”
   → 간단한 설명·분석이면 **Mistral Large**.
4. “이 주장들의 논리적 차이를 깊게 비교해줘.”
   → **Claude Opus**, 미선택이면 **Qwen Max**.
5. “지금 정리한 내용으로 발표 대본 써줘.”
   → **Claude Sonnet**, 미선택이면 **Qwen Plus**.

| 예외 발생 | 처리 흐름 제안 |
|---|---|
| PDF를 올렸지만 파일 첨부 기능이 아직 제공되지 않음 | 텍스트 발췌 입력 안내 → 발췌문 범위에서 요약 진행 |
| 자료에 없는 출처나 수치가 답변에 등장함 | 원문과 대조 → 근거 없는 내용을 제외하도록 재요청. 검색 기능이 없으면 실제 출처를 찾았다고 표현하지 않음 |
| 무료 사용량이 끝남 | 다음 제공 시점·유료 선택 안내 → 사용 가능한 다른 AI로 전환할지 선택 → 품질·비용 차이 표시 |

**핵심:** 요약·번역과 깊은 분석을 구분하고, 제공한 자료의 범위와 AI가 덧붙인 설명을 구별한다.

## 4. 이지훈 · 직장인

**상황:** 회의 메모를 보고서와 거래처 메일로 정리한다.

**기본 흐름**

1. 회사에서 허용한 범위의 익명화된 메모 입력.
2. “결정사항·담당자·마감일을 표로 정리해줘.”
   → **Qwen Plus**.
3. “이 내용을 바탕으로 주간 보고서 초안 써줘.”
   → **Claude Sonnet**.
4. “거래처에 보낼 메일을 작성해줘.”
   → **Claude Sonnet**.
5. “메일을 영어로 번역해줘.”
   → **Qwen Plus** → 사람이 검토 후 발송.

| 예외 발생 | 처리 흐름 제안 |
|---|---|
| 메모에 담당자나 기한이 없음 | 임의로 채우지 않고 “미정” 표시 → 사용자에게 필요한 정보 확인 → 보고서에 반영 |
| 같은 항목에 서로 다른 금액·날짜가 있음 | 충돌 항목을 보여 줌 → 사용자가 확정 → 확정값으로 보고서·메일 수정 |
| “이 메일 바로 보내줘” 요청 | 자동 발송이 MVP 범위 밖임을 안내 → 복사할 수 있는 최종 메일 제공 |

**핵심:** 문장이 자연스러운 것보다 원문의 숫자·담당자·기한이 정확히 유지되는지가 중요하다.

## 5. 최수진 · 카페 운영자

**상황:** 주말 신메뉴 행사 홍보물과 리뷰 답글을 만든다.

**기본 흐름**

1. 메뉴명·가격·행사 기간 입력.
2. “인스타그램에 올릴 홍보 글 써줘.”
   → 글쓰기이므로 **Claude Sonnet**, 미선택이면 **Qwen Plus**.
3. “이 행사 포스터 만들어줘.”
   → **Nano Banana**.
4. “홍보 글을 영어로도 번역해줘.”
   → **Qwen Plus**.
5. “이 리뷰에 정중한 답글 써줘.”
   → 답글 작성이므로 **Claude Sonnet**, 미선택이면 **Qwen Plus**.

| 예외 발생 | 처리 흐름 제안 |
|---|---|
| 메뉴 가격이나 행사 기간을 입력하지 않음 | 필요한 항목 확인 → 임시 가격을 만들지 않고 입력 후 진행 |
| 포스터의 가격·메뉴명이 잘못 생성됨 | 확정 문구와 비교하도록 안내 → 재생성 또는 외부 도구에서 텍스트 편집 |
| Mistral·Nano Banana만 담았는데 홍보 글을 요청함 | 현재 PRD의 글쓰기 대체 순서에는 Mistral이 없으므로 Claude·Qwen 담기 안내 |

**정책 제안:** 소상공인용 짧은 홍보 글·리뷰 답글을 Mistral이 맡게 하려면 ‘짧은 실용 글쓰기’ 분류를 추가해야 한다. 기존 페르소나의 Mistral 활용 설정과 PRD 라우팅을 맞출 필요가 있다.

## 6. 한지우 · 프리랜서 디자이너

**상황:** 고객 브리프로 카피와 이미지 시안을 만들고 수정한다.

**기본 흐름**

1. 고객별 새 대화에서 승인된 브리프 입력.
2. “요구사항과 금지사항을 정리해줘.”
   → **Qwen Plus**, 미선택이면 **Mistral Large**.
3. “브랜드 소개 문구와 시안 설명을 써줘.”
   → **Claude Sonnet**.
4. “두 번째 방향으로 이미지 시안 3개 만들어줘.”
   → **Nano Banana**.
5. “선택한 시안의 색상만 바꿔줘.”
   → **Nano Banana**: 선택한 결과를 기준으로 변형.

| 예외 발생 | 처리 흐름 제안 |
|---|---|
| “두 번째 것”이 문구인지 이미지인지 불분명함 | 대상 결과를 선택하게 함 → 선택 후 실행 |
| 새 수정 지시가 기존 금지사항과 충돌함 | 충돌 조건 표시 → 기존 조건 유지·새 지시 적용 중 확인 → 수정 |
| 고객이 SVG·편집 가능한 원본 파일을 요구함 | 해당 형식 제공이 보장되지 않음을 안내 → 이미지 다운로드 후 전문 편집 도구로 작업 |

**핵심:** 수정할 때 무엇을 바꾸고 무엇을 유지할지 명확히 한다. 다른 모델로 다시 받으면 추가 차감된다는 점도 표시한다.

## 7. 윤태호 · 온라인 판매자

**상황:** 상품 설명을 해외용으로 번역하고 반복 문의에 답한다.

**기본 흐름**

1. 상품별로 확정 규격·배송·반품 조건 입력.
2. “이 정보로 상품 설명 써줘.”
   → **Claude Sonnet**, 미선택이면 **Qwen Plus**.
3. “영어와 일본어로 번역해줘.”
   → **Qwen Plus**.
4. “이 고객 문의에 배송 정책을 바탕으로 답글 써줘.”
   → **Claude Sonnet**, 미선택이면 **Qwen Plus**.
5. 사람이 숫자·단위·정책을 확인한 뒤 상품 등록·답변 전송.

| 예외 발생 | 처리 흐름 제안 |
|---|---|
| “오늘 주문하면 언제 도착해?”라고 묻지만 재고·배송 조회 연결이 없음 | 배송일을 확정하지 않음 → 판매자가 확인한 일정 입력 → 답변 작성 |
| 번역 과정에서 규격·단위·반품 조건이 달라짐 | 원문과 번역의 중요 항목 대조 → 오류 부분 수정 |
| 다른 상품의 대화에서 새 상품 설명을 요청함 | 적용할 상품 확인 → 새 상품 정보로 전환하거나 새 대화 안내 |

**정책 제안:** 정해진 정책에 따른 짧은 답글은 Mistral로 처리하도록 별도 분류를 두면 페르소나의 저비용 반복 응대 목적과 맞는다. 현재 PRD에는 이 글쓰기 분기가 없다.

## 모든 페르소나에 필요한 예외 처리

| 상황 | 처리 원칙 |
|---|---|
| “대본·음성·썸네일 전부 만들어줘”처럼 여러 작업을 한 번에 요청 | 작업을 나눠 제시 → 먼저 할 단계 확인 → 순서대로 진행 |
| 자동 선택한 AI가 작업에 맞지 않음 | 실행 전 예상 AI 확인 또는 결과에서 다른 모델 선택 → 추가 차감 표시 |
| 기본 AI가 장애 상태임 | 같은 작업을 수행할 대체 AI·비용 안내 → 전환. 음성·이미지는 대체 AI가 없으면 재시도 안내 |
| 요청이 실패했는데 완료 여부가 불명확함 | 성공 여부와 차감 내역 확인 → 중복 생성·중복 차감 방지 |
| 이전 결과의 일부만 바꾸려는 요청 | 수정 대상과 유지 조건을 확인 → 해당 결과를 기준으로 처리 |
| 크레딧이 부족함 | 추가 충전·작업량 축소·사용 가능한 대체 AI 선택 후 재개 |

**정책 확정이 필요한 부분:** PRD의 “다시 받기 추가 차감·환급 없음”과 공급사 오류로 인한 실패 처리는 구분해야 한다. 기술적 실패 시 차감·재시도 정책은 별도로 정하는 것이 필요하다.

## 현재 구현과의 차이

2026-11-09 시나리오 작성 시 확인한 [라우팅 설정](../web/lib/config.js)은 요약·번역에 Gemini를 사용하고 Qwen·Mistral·음성 유형은 아직 없다. [서버](../web/server.js)는 이미지 생성에 마지막 요청만 전달한다. 따라서 이 기획을 구현하려면 PRD에 맞춘 라우팅 정리와 이미지 생성에 이전 맥락 전달이 먼저 필요하다. 이 문서를 추가하는 작업에서는 코드를 변경하지 않는다.
